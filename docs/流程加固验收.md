# 流程加固验收报告（2026-10-08，小k执行）

## 背景：确认的 6 类工程缺陷

| # | 缺陷 | 证据 |
|---|------|------|
| 1 | HN 绕过 500 字正文检查、把热议日期当发布日期、占满候选池 | 旧 `rank.filter_candidates`：`wc(content)<MIN_WORDS and not is_hn` 豁免 + `is_hn and c.get("publish_date")` 直接用 HN created_at；`_candidates/Daily-Brief-2026-10-07-candidates.json` 8 篇候选 word_count 仅 6–16，全是 HN 一句话 stub |
| 2 | validator 默认分别取最新简报和最新候选 → 跨日错配 | 旧 `validate_brief.py` 两个 `find_latest` 独立探测 |
| 3 | validator 不查实际日期窗口与正文质量 | 旧校验只查 date_verified 布尔位，不查 window、不查 word_count、不查日期精度 |
| 4 | 畸形反斜杠 URL 放行 | 旧 `norm_url` 只查 `startswith("http")`；2026-10-07 池内即有一条（回放实测"非法 URL"拒收） |
| 5 | 采集无锁/重复执行/累积超时 | 旧 `_main` 无锁、直接覆盖写、各阶段串行超时叠加（TG 10×20s + ACS 180s + HN 12×15s） |
| 6 | 点赞区"存在即跳过"残留旧链接 | 旧 `like_links.add_like_section`：`if SECTION in text: return False` |

## 实改文件清单

### modules/filter.py
- 新增 `is_valid_url`：scheme 必须 http/https、netloc 非空、含反斜杠/空白/控制字符即判畸形；`norm_url` 对畸形 URL 返回 `""`（**拒收，不静默修复**）

### modules/retrieve.py
- 新增 `Budget` 类：全采集共享总截止时间，`timeout(cap)` 把单次超时钳制在剩余预算内
- 新增 `fetch_texts_parallel`：ThreadPoolExecutor 有界并发（`FETCH_WORKERS=4`），单 URL 故障隔离为 None，预算耗尽停止派发
- `fetch_hn`：**created_at 只记入 `hn_discussed_at`（热议日期），不再充当文章发布日期**；publish_date 置空交由文章自身证据判定
- `fetch_telegram_channels` / `fetch_agent_case_share` / `run_cli` / `search_batch_with_tags` 全部接入 Budget；ACS 子进程上限 180s→90s

### modules/rank.py（核心准入重写）
- `filter_candidates` 两阶段：`_cheap_precheck`（不联网）+ 并行补抓正文后统一准入
- **入池硬条件（所有来源同一标准，HN 不豁免）**：正文 ≥500 字（抓到仍不足→拒）；发布日期证据**精确到日**（月精度/未知→拒）；不未来；**必须在采集窗口内**（窗口外不再"打标放行"，直接不入池，杜绝进深度/TLDR/快读）；HN 额外交叉核对（发布日期晚于热议日期→证据矛盾拒收）；news.ycombinator.com 讨论页不入池
- `rank_candidates`：轨交优先 → 发布日期降序 → **HN 积分只在同质量同日内作次序参考**；主题多样性单方向 ≤4（轨交除外）；HN ≤`MAX_HN`；**有合格探索候选时保底 ≤2 席，生活/健康方向优先**

### scripts/collect_brief.py
- `acquire_lock`/`release_lock`：fcntl 非阻塞采集锁，占用即 fail-fast 退出 1
- `atomic_write_json`：mkstemp + os.replace 原子落盘
- `--reuse-cache`：**显式**同日合格缓存复用（第三轮起升级为严格合格校验，见下节）
- **空池熔断**：kept=0 → 退出 1 且**不覆盖已有候选文件**
- 每次运行生成 `run_id` 写入候选 JSON；总预算 `TOTAL_BUDGET_S=480`
- 速览 leftover：未知日期一律剔除（**未知日期含速览禁止交付**；第三轮起进一步要求日精度窗口内证据）

### scripts/validate_brief.py
- **日期配对**：从文件名提取日期，简报 ↔ 候选必须同日（显式参数不一致→FAIL；缺省只找同日期候选，缺失→FAIL，不再"各取最新"）
- 新增校验 ⑦未知日期 leftover 出现在简报任何位置→FAIL；候选产物携带未验证 leftover→FAIL ⑧引用候选的 publish_date 必须日精度且在候选窗口内、word_count ≥500 ⑨简报 `<!-- run_id: ... -->` 标记必须与候选一致

### scripts/like_links.py
- **幂等重建**：不再"存在即跳过"；按当前参考资料整体重建点赞区并原子写回，重复执行结果一致，参考资料变更后旧链接不残留

### scripts/brief_record.py
- 简报/候选文件名日期跨日错配→拒绝记录；同日记录改为**幂等 upsert（可重建，替换而非追加）**；写盘原子化

### scripts/replay_candidates.py（新增，离线回放入口）
- `python3 scripts/replay_candidates.py 2026-10-07`：只读、不联网、不写文件，按新标准回放历史候选池
- 合格 0 篇 → `[REPLAY_REFUSED]` 明确拒绝交付，**不编造正文、不补写日期**

### scripts/likes.py
- 重复的 `norm_url` 同步畸形 URL 拒收（其 docstring 本就声称与 collect_brief 语义一致）

## 行为变化须知（对写作/投递流程）

1. 候选池收窄是必然结果：stub/旧文/无日期内容不再入池，候选数会比以前少；**空池即熔断不出简报**，宁缺毋滥。
2. 简报与候选按文件名日期严格配对，补写历史日期简报时必须配同日期候选 JSON。
3. 写简报时建议在文首写入 `<!-- run_id: <候选JSON的run_id> -->`，validator 会核对。
4. 速览区不再有"（日期未验证）"放行通道：无日期证据的 leftover 不会进候选产物。
5. `like_links.py` 现在每次都重建点赞区，可安全重复执行。

## 2026-10-08 第二轮加固（补齐主席复审遗漏）

### 实改清单

1. **发布日期证据链重写**（`modules/filter.py`）：新增 `extract_date_evidence`，按 **JSON-LD → HTML meta → `<time datetime>` → 署名发布时间标记（发布时间/发布于/Published on…附近日期）→ URL 日精度 → 标题日精度 → URL 月精度** 取证，返回 `publish_date/date_source/evidence/precision`；**普通正文第一处日期不再冒充发布时间**（常为事件时间）；所有日期过合法日历校验（2026-02-30 之类拒收）；URL 月精度不再抢在正文/标题精确日前。`extract_publish_date` 保留为兼容包装。
2. **正文抓取保 metadata + 提高上限**（`modules/retrieve.py`）：新增 `fetch_article`（清洗前先提取 JSON-LD/meta/`<time datetime>`），`fetch_article_text` 保持返回字符串的兼容接口；默认 limit 2500→6000（英文 500 词 ≈3000+ 字符，原上限会把合格英文正文截到准入线以下），`CONTENT_LIMIT` 同步 3000→6000；`fetch_texts_parallel(with_metadata=True)` 供准入阶段取日期证据。
3. **validate 不再只信元数据**（`scripts/validate_brief.py`）：引用候选须 **真实 content 实测 wc ≥500**（word_count 元数据虚标即 FAIL）；必须带 `date_source`（旧格式布尔位不能冒充验证）与 `date_precision=day`；**候选带 run_id 时简报必须标注且一致**（原来只在错配时拒绝）。
4. **生活/健康保底**（`modules/rank.py`）：全池有合格生活/健康条目时各保 ≥1 席（不限探索候选），保底席**计入主题上限与 HN 上限**，方向 None 的 HN 条目不能再挤占；探索保底 ≤2 席不变，与保底席去重。
5. **预算闭环**（`modules/retrieve.py` / `rank.py` / `collect_brief.py`）：`Budget.derive` 派生子预算——搜索/源采集用子预算（480-150s），**为正文抓取与准入阶段预留 150s**；偏好/探索查询先行，默认查询轨交优先；`anysearch_http_batch`/`anysearch_http_extract`/`fetch_hn` 全部接同一截止时间。**说明**：这是"共享墙钟截止时间 + 单次 socket 超时钳制于剩余预算"的预算化约束，已派发线程最多超出单次 socket 上限，不是数学意义上的严格硬截止。
6. **查询临时文件**（`modules/rank.py`）：`/tmp/brief_queries_*` 固定名改为 `tempfile.mkstemp`（`tmp_dir` 可指定目录），finally 清理，异常也不残留。

## 2026-10-08 第三轮加固（验收补洞：同日坏缓存与速览日期证据）

### 实改清单

1. **`load_valid_cache` 严格合格化**（`scripts/collect_brief.py`）：同日 `generated_at` 只是必要条件；还须 `run_id` 存在、窗口与当日一致（`window.end == today`）、每条候选过准入同级校验——URL 合法、`date_precision == "day"`、`date_source`/`date_evidence` 齐全、`publish_date` 落在窗口内、**真实 content 实测 wc ≥500**（word_count 元数据仅参考）；速览条目同标准（日精度/来源/窗口/URL）。任一条不合格即 MISS，**不再复用同日旧坏池**。
2. **速览日期统一证据链**（`pick_leftover_item` / `pick_homepage_latest_item`）：新增 `_leftover_date_evidence`——一律走 `extract_date_evidence`，只收**日精度、有 date_source/evidence、落在本次窗口内**的原文日期；月精度/无证据/未来/窗口外一律拒收，无证据即跳过。**不再信任条目自带 `publish_date`/`date_verified` 布尔位**（TG 搬运日不是原文日）；返回条目携带 `date_source`/`date_evidence`/`date_precision`。
3. **主页 extract 纳入预算**：`retrieve.anysearch_extract` 接 `budget`（预算耗尽不发任何网络请求）；`pick_homepage_latest_item` / `pick_leftover_item` / `build_source_leftovers` 透传总 Budget，特殊源主页提取不再绕过预算。
4. **validator 速览同标准**（`scripts/validate_brief.py`）：leftover 除 date_verified 外，还须日精度、带 `date_source`/`date_evidence`、落在候选窗口内、URL 合法——导航页/旧日速览不得旁路，候选产物携带不合格速览即 FAIL。

# 批次隔离与交付验收（2026-10-10）

同日重复采集曾覆盖候选，agy/重试又共用简报路径，使已完成简报无法与原候选配对。
此次改为按 run_id 独立保存全流程证据，并同步 Hermes 定时任务与 today-brief 技能的交接规则。

## 实现

- `modules/run_store.py`：批次 manifest、初始候选快照、独立审核副本、原子写入与不覆盖快照。
- `collect_brief.py`：每次 stdout 提供精确候选及独立简报路径；日期候选别名仅用于状态与缓存。
- `validate_brief.py`：自动查找同 run_id 快照，保存完整输入、哈希及 PASS/FAIL 输出；校验期间输入被修改即拒绝。独立批次预检不登记为交付。
- `run_agy.py`：同批次写入锁覆盖子进程运行期，日志及 prompt 留在批次内；真实超时结束子进程组；非零退出不因旧产物存在而冒充成功。
- `finalize_brief.py`：主席读稿后统一预检→点赞区→复检→最终快照→登记及日期发布入口。已有当日发布版不可被另一批次覆盖，已发布批次可幂等返回原快照，哈希变化拒绝交付。
- `brief_record.py`：run_id 配对守卫，保存精确路径与内容哈希；拒收脚本禁止更改已发布批次。
- Hermes 定时任务继续保持每日 08:30 和原模型、投递配置；任务全文保存在 `hermes-dailybrief-task.txt`，today-brief 技能加了优先级明确的新交接规则。

## 验证范围

复审后 190 项离线 unittest 全部通过，覆盖既有日期/正文/探索/拒收规则及新增批次隔离、默认按 run_id 选池、
校验中修改、不可覆盖快照、幂等发布、已发布候选被修改、同批次锁、agy 非零退出。
模拟 agy 子进程不调用真实模型。未主动触发新的简报采集或投递。

结构校验不能证明 LLM 摘要中的所有事实正确，主席原文复核仍是交付前步骤。
日期窗口仍沿用既有日粒度逻辑，本轮只修复批次追溯与交付，不扩大到时效规则改造。
